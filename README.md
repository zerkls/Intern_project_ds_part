# ИИ-помощник по складскому учёту и закупкам спа-оператора

Демонстрационный MVP. Реализованы все три части: нормализация записей движения товара,
прогноз потребности с рекомендацией закупки и разбор вопросов пользователя с ответом.

## Запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

pytest                      # тесты
python main.py normalize    # разбор записей M1–M8 из dataset.json
python main.py forecast     # прогноз и закупка по 3 позициям на 30 и 90 дней
python main.py forecast --explain   # то же с текстовыми объяснениями
python main.py ask          # 15 вопросов пользователя: таблица и доля «требуется уточнение»
python main.py ask --explain        # то же с полными текстами ответов
python main.py all          # весь пайплайн одной командой
```

Гибридный разбор вопросов: правила и GigaChat (необязательно, без ключа работают только правила):

```bash
export GIGACHAT_CREDENTIALS=...      # ключ авторизации из личного кабинета GigaChat API
python main.py all --llm
```

Сервер GigaChat использует сертификат НУЦ Минцифры. Если возникает ошибка SSL, скачайте
корневой сертификат Минцифры и укажите путь к нему: `export GIGACHAT_CA_BUNDLE_FILE=путь/к/сертификату.crt`.

## Архитектура

```
catalog.json              справочник товаров (Приложение 2)
dataset.json              тестовые данные (Приложение 1)
main.py                   CLI
spa_assistant/
  config.py               все пороги, словари синонимов, единицы измерения
  catalog.py              загрузка справочника
  normalize.py            Часть 1: normalize_movement(text) -> dict
  forecast.py             Часть 2: forecast_demand(history, sku, horizon_days, params) -> dict
  qa.py                   Часть 3: answer_question(question, context) -> (dict, float, str)
  llm.py                  необязательный разбор вопроса через GigaChat
tests/test_normalize.py   тесты разбора дат, единиц, операций, SKU
tests/test_forecast.py    тесты округления закупки, пропусков, сдвига уровня, confidence
tests/test_qa.py          тесты разбора вопросов, уточнений и происхождения чисел в ответах
requirements.txt          зависимости: pytest и gigachat (для гибридного режима)
setup.cfg                 настройки стиля кода: PEP8 с длиной строки до 99 символов
RESULTS.md                результаты всех трёх частей, обоснование подходов и порогов
```

Данные из Приложения 1 собраны в один `dataset.json` с тремя ключами: `movements`
(записи M1–M8 для Части 1), `history` (расход, остатки и поставки для Части 2) и
`questions` (15 вопросов для Части 3). Сами данные скопированы без изменений.

`normalize_movement` работает на правилах и регулярных выражениях, без LLM.
Найденные фрагменты по очереди вырезаются из текста (дата → партия → документ →
объект → SKU), после чего ищутся операция и количество.
Количество пересчитывается в базовую единицу позиции из справочника.

`forecast_demand` не использует LLM. Ряд недельного расхода очищается (пропуски
исключаются, устойчивый сдвиг уровня обрезает старую историю, одиночные выбросы
обрезаются по MAD), затем строится линейная регрессия с трендом или среднее.
По прогнозу считаются страховой запас, точка заказа и объём закупки, округлённый до
минимальной партии и упаковки из справочника. Параметры позиции передаются из
catalog.json, и все числа в объяснении берутся из входных данных.

`answer_question` разбирает вопрос в интент и сущности: позицию, объект, период, лимит,
коэффициент загрузки. По умолчанию работают правила. С `--llm` включается гибрид: интент
берётся у правил, если они уверены, иначе у GigaChat; кандидаты позиции объединяются, чтобы
модель не могла угадать одну позицию из нескольких подходящих. Если интент
неоднозначен или не хватает обязательных параметров, возвращается `unknown` с уточняющим
вопросом. Иначе ответ собирается по шаблону из результатов `forecast_demand` и справочника.
LLM не пишет текст ответа, поэтому придумать числа не может.
